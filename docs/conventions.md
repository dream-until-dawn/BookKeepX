# 开发约定

## 1. Git 工作流

- `main`：只接受合并，始终可发布。**合并到 main、打 tag 需项目负责人确认。**
- 分支命名：`feat/<模块>-<简述>`、`fix/…`、`docs/…`、`probe/…`、`chore/…`
- 提交信息：`<类型>(<范围>): <中文简述>`，类型取 feat / fix / docs / test / refactor / chore / probe
  - 例：`feat(core): 新增元转分的金额解析`
- 版本号：语义化版本，P0 → `v0.0.x`，P1 → `v0.1.0`

## 2. 模块边界

- `packages/core` 禁止引入框架、数据库、网络、文件系统依赖；
- `apps/server` 的 `routes` 不直接访问数据库，必须经过 `service → repository`；
- 跨模块只通过对方的公开入口（`index.ts`）引用，禁止深路径引用内部文件；
- 前端 `features/*` 之间不互相引用，公共部分下沉到 `shared/`。

## 3. 测试要求

**永远绿的测试等于没有测试。** 每个功能点必须同时包含：

- **正向用例**：合法输入 → 正确结果；
- **反向用例**：非法 / 边界输入 → 明确的错误（抛错类型、错误码、HTTP 状态码）；
- **边界用例**：0、最大值、空文件、只有表头、重复导入、跨月 / 跨时区等。

补充要求：
- 修 bug 先写一个能复现它的失败测试，再修；
- 新测试写完后，**临时破坏被测代码确认测试会变红**，再恢复（在 PR 描述里注明已做）；
- core 包后续引入变异测试（Stryker）量化测试有效性；
- 集成测试连接真实 PostgreSQL（测试容器），不 mock 数据库；
- 解析器测试使用 `fixtures/` 下的脱敏样本文件，样本中不得出现真实姓名、卡号、订单号。

## 4. 代码风格

- TypeScript `strict` 全开，禁止 `any`（确需时写注释说明）；
- Biome 统一代码检查与格式（见 [ADR-0005](./adr/0005-lint-and-format.md)），`pnpm check` 通过才能提交；
- **注释用中文**：每个导出的函数 / 类型写 JSDoc 说明用途、参数、返回值和会抛出的错误；复杂分支写"为什么"而不只是"做什么"；
- 命名用英文、语义化；业务术语对照见下表。

| 中文 | 代码命名 |
|---|---|
| 流水 / 一笔账 | transaction |
| 收支方向 | direction（income / expense） |
| 资金账户 | account |
| 分类 | category |
| 导入批次 | importBatch |
| 对方 / 商户 | counterparty |
| 金额（分） | amountCents |

## 5. 外部信息

来自兄弟会话、第三方文档、网络的信息，**写进代码或文档前必须自行验证**（跑一遍、查源码或查官方文档），并在 PR 描述中注明验证方式。
