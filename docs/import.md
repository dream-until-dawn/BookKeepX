# 账单导入设计（P1-6）

- 依据：[ADR-0003 解析模板](./adr/0003-import-templates.md)、[ADR-0004 分类与规则](./adr/0004-categories-and-rules.md)、P0-1 ~ P0-1e 探针结论、[数据模型](./data-model.md)
- 范围：内置模板（微信 xlsx、支付宝 csv、招行 PDF）的上传 → 识别 → 解析 → 自校验 → 退款关联 → 去重 → 自动分类 → 预览 → 提交 → 整批撤销；导入页面
- 不在本步：用户自定义模板向导（P1-7）、用户规则管理与"从修改中学习"（P1-8）

## 1. 模块划分（对架构的一处调整）

架构文档原计划把导入引擎放在 `packages/core`。实现时发现引擎依赖 exceljs、pdfjs-dist 等体积很大的库，而 `core` 同时被前端引用，放在一起会拖大前端包。因此：

| 包 | 内容 | 谁用 |
|---|---|---|
| `packages/core` | 金额、时区、预置分类、**分类规则引擎**（纯函数，无重依赖） | 前端 + 服务端 |
| `packages/importers`（新增） | 文件读取、通用解析引擎、内置模板、自校验、退款关联 | 仅服务端 |

## 2. 流程

```
上传文件（≤10 MB）
  ① 按文件头识别类型（xlsx / pdf / csv），不信任扩展名
  ② 自动识别模板（ADR-0003 打分）
       高置信 → 继续；有候选但不确定 → 返回候选让用户选，用户选定后重新提交
       无候选 → 提示暂不支持（P1-7 起可自定义模板）
  ③ 解析 + 自校验（汇总比对 / 余额链）→ 不通过则拒绝导入，并列出问题
  ④ 文件内退款关联（P0-1e）
  ⑤ 与账本已有数据比对：
       同来源重复：平台单号已存在 / 银行去重键已存在 → 标记"已导入过"，默认不导入
       退款的原消费在以前的导入里：按单号前缀在库中查找（支付宝）
       跨来源重复（ADR-0004 Q2-B）：见 §4
  ⑥ 自动分类：用户规则 > 系统规则 > 来源映射（ADR-0004 决策链）
  ⑦ 生成预览，存入 import_batches.preview（状态 previewing，24 小时后过期）
预览页：用户可以改分类、取消勾选某些行
  ⑧ 提交：一个数据库事务内写入全部流水、更新批次状态
整批撤销：删除该批次写入的全部流水（其他批次对它们的退款 / 重复引用先解除）
```

## 3. 接口

| 接口 | 说明 |
|---|---|
| `POST /api/ledgers/:ledgerId/imports` | 上传（multipart：`file`，可选 `templateId`、`accountId`）。结果三种之一：预览 `{ status: 'preview', batch }`；需要选择模板 `{ status: 'choose_template', candidates }`；校验失败 422 `IMPORT_VERIFY_FAILED` 带问题列表 |
| `GET /api/ledgers/:ledgerId/imports` | 导入历史 |
| `GET /api/ledgers/:ledgerId/imports/:batchId` | 批次详情（预览中的批次含预览行） |
| `POST /api/ledgers/:ledgerId/imports/:batchId/commit` | 提交：`{ overrides: [{ index, categoryId?, include? }] }` |
| `POST /api/ledgers/:ledgerId/imports/:batchId/revert` | 整批撤销 |
| `DELETE /api/ledgers/:ledgerId/imports/:batchId` | 放弃预览 |

**同一文件重复上传**（文件指纹相同，且之前已提交）：照常解析，但所有行都会被标记为"已导入过"，预览里一目了然。

## 4. 跨来源重复（ADR-0004 Q2-B）

同一笔消费既出现在平台账单（支付宝 / 微信，用银行卡付款），又出现在银行流水。判定条件：

- 同一天、同金额；
- 平台记录的支付方式里包含该银行卡的尾号（如"招商银行储蓄卡(1032)"），且银行记录属于尾号 1032 的账户。

处理：两条都保留，**银行那条**的 `duplicate_of_id` 指向平台那条，不计入统计。无论先导入哪一边都会在后导入时建立关联。

理财申购 / 转入零钱通这类（Q2-A）由分类规则识别为中性，不走重复关联。

## 5. 资金账户的对应

- 用户在上传时可以选择账户；
- 不选时自动推断：微信账单 → 唯一的"微信"类型账户；支付宝同理；银行流水 → 卡号后四位与文件中账号尾号一致的账户；推断不出时为空；预览页可补选账户，用同一文件重新识别（从导入历史继续的预览没有原文件，需重新上传）。

## 6. 预览行的状态

| 状态 | 含义 | 默认是否导入 |
|---|---|---|
| `new` | 新记录 | 是 |
| `duplicate` | 本账本已导入过（同单号 / 同去重键） | 否 |
| `skipped` | 账单中按规则跳过的（交易关闭无退款、0 元） | 否（只展示） |

另外带标记：`refund`（退款及其关联情况）、`crossSourceDuplicate`（跨来源重复，将导入但不计入统计）。

## 7. 安全

- 文件大小上限 10 MB，只接受 xlsx / pdf / csv（按文件头判断）；
- 不保存原始文件（data-model.md Q1），只存文件指纹和每行原始数据；
- 解析在服务端进行，模板中不含可执行代码、不含正则（ADR-0003）。
