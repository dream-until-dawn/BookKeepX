# P1-8 分类规则

## 设计与边界

规则属于账本，查看需要成员权限，创建、修改、删除和应用需要 owner/editor 权限。沿用 ADR-0004 声明式条件和分类器；不支持正则。数字优先级越小越早执行，同优先级先创建的规则优先，再按 id 稳定排序，保证导入和历史应用一致。新规则的试跑排在同优先级旧规则之后；每个账本最多 200 条规则。

编辑规则后先预览再保存。预览显示最近 100 笔命中样本、命中的其他规则及最终胜出规则；冲突指多条有效规则为同一笔流水给出不同动作，不表示系统会同时执行。历史应用针对当前账本全部有效流水，先返回变更清单和快照摘要，确认时重新计算；规则、分类或流水变动导致摘要不同则返回 409，要求重新预览。一次最多处理 10000 笔有效流水，超出时明确拒绝，不做静默截断。

手动指定的分类永远不被覆盖。退款及有关联退款的原消费不参与历史自动重分类，避免改变退款统计口径；跨来源重复关系保持不变。历史应用从 original_direction（若有）重新分类，可恢复被旧规则改为中性的流水。只写入实际变化，重复应用不会重复累计命中。

P1-8 增加 `transactions.original_direction` 和 `import_source`，分别保留改向前方向、与单号无关的账单来源。旧手工流水回填方向，旧导入流水无法可靠还原原方向时保留空值，历史应用以当前方向为基线。旧来源可从单号或内置模板确定时回填；旧自定义模板无单号且模板已变更/删除时不猜测来源，此类记录的来源条件可能无法命中。历史应用读取导入批次户名参与本人识别。

预览使用 repeatable-read 一致快照；应用在短事务内锁住流水、规则、分类、用户和导入批次表后重新计算摘要。当前有界同步实现会暂时阻塞其他账本对这些表的写入，锁等待上限 5 秒；大规模部署前应改为分批任务和行版本控制。

学习建议由用户改分类后主动确认：预填「对方等于该商户 + 改向前方向」，目标为中性时同时设置改向动作，用户仍可编辑、试跑并保存；不自动创建规则。导入预览的分类修改提供同样入口。规则删除不改已有流水，后续历史应用才重算。

## 接口

前缀 `/api/ledgers/:ledgerId/category-rules`：

- GET /：列表，含启用状态、优先级、来源及命中次数。
- POST /：创建；PATCH /:ruleId：完整更新；DELETE /:ruleId：删除。
- POST /preview：试跑草稿，携带可选 ruleId 替换已有规则，返回命中样本及冲突。
- POST /history-preview：按已保存规则计算历史变化，返回摘要与最多 100 条变化样本。
- POST /apply：携带摘要，再核验后原子应用；不允许客户端指定任意更新值。

## 验证计划

条件组合、非法字段/操作符/空关键词/越界金额、稳定优先级；跨用户和 viewer 越权；隐藏/外账本分类；手动分类保护、退款保护、方向恢复、冲突胜出；快照过期拒绝和重复应用幂等；界面编辑后使预览失效、学习需确认。故意破坏保护条件，确认对应测试失败后恢复。
