# ADR-0006 多账本：数据隔离的单位是"账本"

- 状态：已采纳（负责人 2026-09-24 决定，data-model.md Q4）
- 日期：2026-09-24

## 背景

记账常见的需求是"个人账本 + 家庭账本"，家人共同记一本账。若一开始只按用户隔离数据，以后再加账本需要给几乎每张表加字段、改全部查询和权限判断，代价很大。

## 决策

1. 新增 `ledgers`（账本）与 `ledger_members`（账本成员）两张表；
2. **业务数据归属账本**：`accounts`、`categories`、`transactions`、`import_batches`、`category_rules`、`source_hint_mappings` 带 `ledger_id`；
3. **个人工具归属用户**：`import_templates`（解析模板描述的是文件格式，不是账本数据）、`sessions`、`users.self_names`；
4. 流水与导入批次另记 `created_by`（谁记的），共享账本里能看到每笔是谁记的；
5. 成员角色：`owner`（所有者，可管理成员、删除账本）、`editor`（可记账、导入、改分类和规则）、`viewer`（只读）；
6. **权限检查的唯一入口**：服务端所有账本内的操作都先经过"成员与角色校验"，再以 `ledger_id` 过滤数据。仓储层不接受没有经过校验的账本 id；
7. MVP：注册时自动创建一个默认账本（`users.default_ledger_id`），并写入预置分类；界面上暂不开放新建账本、邀请成员和切换账本（P2）。

## 被否决的备选

- **只按用户隔离，以后再说**：迁移代价大，且家庭共享是记账应用的常见需求。
- **账本内每个用户各自一套分类**：共享账本里分类不统一，统计无法合并。

## 后果

- 每个账本内的查询都多一次成员校验（可缓存，成本很低）；
- "转给自己"的识别在共享账本中要扩展为"转给账本内的成员"（P2 开放共享时处理）；
- 删除用户时：其独占的账本一并删除；共享账本的所有权需先转移（P2 处理，MVP 只有独占账本）。
