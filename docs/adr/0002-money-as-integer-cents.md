# ADR-0002 金额以"整数分"存储

- 状态：提议中（待确认）
- 日期：2026-09-24

## 背景

JavaScript 的 number 是二进制浮点数，`0.1 + 0.2 !== 0.3`。记账系统里金额误差不可接受；账单里的金额又常带 `¥`、千分位逗号、正负号、"-"前缀等多种写法。

## 决策

1. 数据库列 `amount_cents BIGINT NOT NULL CHECK (amount_cents > 0)`，单位为"分"；
2. 收支方向由独立字段 `direction`（income / expense）表达，金额本身恒为正；
3. 字符串 → 分的转换**只允许**走 `packages/core/money` 的 `parseYuanToCents`，内部按字符串拆分整数与小数部分计算，**不经过浮点数**；
4. 分 → 展示字符串只允许走 `formatCents`；
5. 超过 2 位小数、非法字符、空串一律报错，不静默四舍五入。

## 补充（P1-1，2026-09-24）：解析与传输规则

**解析 `parseYuanToCents` 接受的写法**（均来自 P0 真实账单）：

| 写法 | 来源 | 结果（分） |
|---|---|---|
| `6`、`21.78`、`0.01` | 支付宝、微信 | 600、2178、1 |
| `¥11.00`、`￥12.90` | 微信旧版 csv、手动输入 | 1100、1290 |
| `1,800.00`、`-2,500.00` | 招行 PDF（带千分位和符号） | 180000、−250000 |
| `602.00元` | 平台账单的汇总行 | 60200 |
| Excel 数字单元格 `2635.95` | 微信 xlsx | 263595 |
| 全角 `１２．５` | 手动输入时的输入法 | 1250 |

**拒绝**（抛出 `MoneyParseError`，带错误码，不静默修正）：空串（EMPTY）、非法字符或多个小数点（FORMAT）、超过两位小数（PRECISION，包括 Excel 浮点误差如 `0.30000000000000004`）、超出安全整数（OVERFLOW）、千分位位置不对如 `1,23.00`（FORMAT）。

**接口传输**：API 中金额一律用整数"分"（`amountCents`，contracts 中的 `centsSchema`），由前端用 `formatCents` 展示；只有用户在表单里输入金额时才传"元"字符串，由服务端用 `parseYuanToCents` 转换。

**图表**：ECharts 需要数字时用 `centsToYuanNumber`，结果只能用于展示，不得再参与任何计算。

## 后果

- 统计求和在数据库以整数完成，无精度问题；
- Drizzle 读取 bigint 需配置为 `number` 模式（安全整数范围内足够：约 900 亿亿分）或 `bigint`，由 P0 探针确认往返正确；
- 多币种（P2+）时新增 `currency` 字段已预留，换算另立 ADR。
