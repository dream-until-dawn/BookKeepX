# 分期路线图

> 每个阶段结束 = 一次合并到 `main` + 打 tag，**均需项目负责人确认**。

## P0 可行性验证 + 工程骨架（目标 tag：`v0.0.1`）

先用最小代码证明关键技术路径走得通，再搭正式骨架。探针代码放 `probes/`，结论写进 `docs/probes/`。

| # | 探针 | 验收标准 | 依赖 |
|---|---|---|---|
| P0-1 | 账单解析 | 用**真实脱敏样本**：微信 / 支付宝 / 至少 1 家银行，能定位表头、识别编码、逐行解析；解析出的收入 / 支出合计与账单文件自带的汇总一致 | 需负责人提供样本 |
| P0-2 | 数据库链路 | Docker 起 PostgreSQL；Drizzle 建表 + 迁移；bigint 金额写入读出一致；按月 `GROUP BY` 聚合结果正确 | — |
| P0-3 | 鉴权依赖 | @node-rs/argon2 在 Windows 本机与 Linux 容器内均可安装、哈希、校验 | — |
| P0-4 | 单仓工程 | pnpm workspace 下 core 被 server / web 同时引用；Vitest 跨包运行；TS 类型联动 | — |
| P0-5 | 图表性能 | ECharts 渲染 1 年（约 3,000 笔）聚合后的数据，首屏可接受 | — |

P0 完成后产出：正式的 monorepo 骨架、CI（lint + 类型检查 + 测试）、docker compose 开发环境。

## P1 MVP（目标 tag：`v0.1.0`）

按依赖顺序，每项一个 feature 分支：

1. `core/money`：金额解析与格式化（先写正反向测试）
2. 数据库 schema + 迁移 + 默认分类种子
3. 鉴权：注册 / 登录 / 登出 / 会话
4. 分类与资金账户管理
5. 手动记账：增删改查、列表筛选
6. 导入管线：自定义模板 → 微信 → 支付宝 → 银行通用字段映射；预览、去重、整批撤销
7. 统计：月度汇总、分类占比、趋势
8. 前端各页面 + PWA 清单
9. Docker 生产镜像 + 部署文档
10. E2E：注册 → 记一笔 → 导入 → 看统计 全链路

## P2 体验与移动端

Capacitor 打包、离线记账与同步、预算、标签、数据导出 / 备份。

## P3 记账 agent

自然语言记账（"午饭 32"）、导入时自动分类、消费分析问答、异常消费提醒。
