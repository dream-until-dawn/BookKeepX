# P0-1 探针结论：账单解析

- 日期：2026-09-24
- 分支：`probe/import-parsing`；代码：[`probes/import-parsing`](../../probes/import-parsing)
- 样本：负责人提供的 3 份**未经修改的真实导出文件**（仅存本地 `samples/`，已 gitignore）
- 结论：✅ **三种来源均可可靠解析**，但发现 4 项必须纳入设计的问题（见第 3 节）

## 1. 结果总览

| 来源 | 文件形态 | 解析笔数 | 自校验方式 | 结果 |
|---|---|---|---|---|
| 微信支付 | xlsx，单表，表头在第 18 行 | 56 | 文件自带汇总：笔数 + 分方向金额 | ✅ 完全一致 |
| 支付宝 | csv，**GBK**，表头在第 24 行 | 399 | 文件自带汇总 | ✅ 一致（修正口径后，见 3.3） |
| 招商银行 | **PDF**（带文字层），4 页 | 82 | **余额链**：上笔余额 + 本笔金额 = 本笔余额 | ✅ 全链贯通 |

测试：35 个（金额解析正反向、合成数据正反向、真实样本正反向）。另做 6 项"故意改坏代码"验证，均能被测试抓到。

## 2. 各来源格式要点

**微信（xlsx）**
- 前 16 行说明为合并单元格；含"共N笔记录 / 收入 / 支出 / 中性交易"汇总
- 列：交易时间 · 交易类型 · 交易对方 · 商品 · 收/支 · 金额(元) · 支付方式 · 当前状态 · 交易单号 · 商户单号 · 备注
- 交易时间是 Excel 日期单元格，**金额是数字单元格**，单号是字符串；空值为 `/`
- 收/支：收入 / 支出 / `/`（中性）

**支付宝（csv）**
- GBK 无 BOM；表头行尾多一个逗号；**订单号尾部带制表符**
- 列：交易时间 · 交易分类 · 交易对方 · 对方账号 · 商品说明 · 收/支 · 金额 · 收/付款方式 · 交易状态 · 交易订单号 · 商家订单号 · 备注
- 自带"交易分类"（餐饮美食、交通出行…）→ 可直接作为分类建议
- 收/支：收入 / 支出 / **不计收支**；状态见到：交易成功、等待确认收货、退款成功、交易关闭
- 文件自己声明"明细直接累加可能与统计金额不一致"

**招商银行（PDF）**
- 有文字层，按 x 坐标定列：记账日期 · 货币 · 交易金额（带符号、千分位）· 联机余额 · 交易摘要 · 对手信息
- 每页重复双语表头，页脚"n/总页数"，末页有"温馨提示"
- **只有日期，没有时间，没有交易单号**
- 对手信息过长时拆成两段，分别在数据行上下约 6pt → 以日期为锚点、±12pt 内拼接

## 3. 必须纳入设计的发现

### 3.1 必须有"中性 / 转账"方向（影响数据模型）
样本中：银行 → 理财（蚂蚁基金）、银行 → 零钱通、支付宝余额宝收益，金额合计数万元。若按"支出 / 收入"入账，统计会严重失真。
→ `direction` 增加 `neutral`（不计入收支统计）；P2 再演进为"转账 = 两个账户间的一对流水"。

### 3.2 跨来源重复（影响导入流程）
同一笔钱会同时出现在银行流水和支付宝 / 微信账单中，且**方向可能不同**（银行记"支出"，支付宝记"不计收支"）。样本中匹配到 2 对，最初按"同方向"匹配时为 0 对。
→ 导入预览阶段做"疑似跨来源重复"提示（同日 + 同额 + 支付方式提到该银行），由用户确认保留哪条。

### 3.3 平台汇总口径不透明（影响校验规则）
支付宝汇总支出比逐行累加少 9 分，定位为一笔"交易关闭"的 0.09 元：**计入笔数、不计入金额**。
→ 每个适配器维护自己的"状态 → 是否入账"规则；"交易关闭"不导入。其余状态（退款成功、等待确认收货）的处理需进一步样本确认。

### 3.4 时间的时区陷阱
xlsx 日期没有时区，读取库按 UTC 解释，而微信声明为 UTC+8。直接入库会整体偏移 8 小时。
→ 规范化阶段统一按"北京时间墙上时间"解释，再转为 timestamptz。
→ 相关测试依赖机器时区才能暴露问题，正式实现需在测试中固定 `TZ`，并加入 UTC 时区下的用例。

## 4. 其他结论

- **银行流水不能靠单号去重**：用 `日期 + 金额 + 交易后余额` 作为去重键（余额使同日同额的两笔也能区分）。
- **"文件自带冗余信息做自校验"应作为导入的质量门槛**：汇总对不上或余额链断开时，拒绝导入并提示，而不是静默入库。
- PDF 解析依赖坐标常量，招行改版会失效；以"列名所在 x 坐标"动态定列可提升鲁棒性（P1 实现）。
- 其他银行格式各异，P1 的"银行流水"先支持招行 PDF + 通用 csv/xlsx 字段映射；每接一家银行需要一份真实样本。
