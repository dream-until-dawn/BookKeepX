# 鉴权设计（P1-3）

- 依据：[架构设计 §6](./architecture.md)、[数据模型](./data-model.md)（users、sessions）、P0-3 探针（argon2id）
- 范围：注册、登录、退出、当前用户、会话续期、登录限流、CSRF 防护；登录页、注册页、未登录跳转
- 不在本步：修改密码、找回密码、邮箱验证、第三方登录、"登录设备"管理页面（P2）

## 1. 接口

所有请求与响应结构定义在 `packages/contracts/src/auth.ts`（zod），前后端共用。

| 接口 | 说明 | 成功 | 失败 |
|---|---|---|---|
| `POST /api/auth/register` | 注册：邮箱、密码、昵称 | 201 返回当前用户，并设置会话 Cookie（注册即登录） | 400 参数不合法；409 `EMAIL_TAKEN`；429 过于频繁 |
| `POST /api/auth/login` | 登录：邮箱、密码 | 200 返回当前用户，并设置会话 Cookie | 401 `INVALID_CREDENTIALS`；429 `TOO_MANY_ATTEMPTS` |
| `POST /api/auth/logout` | 退出：删除服务端会话、清除 Cookie | 204（未登录时调用也返回 204，幂等） | — |
| `GET /api/auth/me` | 当前用户 | 200 `{ id, email, displayName, defaultLedgerId }` | 401 `UNAUTHENTICATED` |

**响应里永远不包含密码哈希**；用户对象只包含上表列出的字段（契约严格模式保证）。

## 2. 密码

- 哈希：argon2id，内存 19 MiB、迭代 2、并行 1（P0-3 实测约 10 ms）；
- 规则：8~128 个字符，不能全是空白；邮箱去首尾空白并转小写；昵称 1~30 个字符；
- **邮箱不存在与密码错误返回完全相同的错误**（"邮箱或密码错误"），并且对不存在的邮箱也执行一次哈希校验，使两种情况的响应时间接近，防止通过报错或耗时探测哪些邮箱已注册。

## 3. 会话

| 项目 | 做法 | 理由 |
|---|---|---|
| 令牌 | 32 字节随机数（base64url） | 不可猜测 |
| 存储 | 数据库只存令牌的 SHA-256 | 数据库泄露也无法冒充登录 |
| Cookie | 名称 `bkx_session`；`HttpOnly`、`SameSite=Lax`、`Path=/`；生产环境 `Secure` | 前端脚本读不到令牌（防 XSS 窃取）；跨站请求不带 Cookie |
| 有效期 | 30 天 | |
| 续期 | 剩余不足 15 天时自动延长到 30 天（"滑动过期"）；`last_seen_at` 最多每 5 分钟更新一次 | 常用就不会掉线，又避免每个请求都写库 |
| 过期 | 过期会话在访问时删除并返回 401 | |

## 4. CSRF（跨站请求伪造）防护

两道防线：
1. Cookie 设置 `SameSite=Lax`：其他网站发起的 POST 请求不会带上会话 Cookie；
2. **所有修改数据的请求（POST / PUT / PATCH / DELETE）必须带请求头 `X-BookKeepX-Client: web`**，否则返回 403 `CSRF_REJECTED`。浏览器不允许其他网站在跨站请求中自定义请求头（除非我们开放 CORS，而我们不开放）。

## 5. 限流

内存计数（单实例自托管足够，多实例时换 Redis），时钟可注入以便测试：

| 场景 | 规则 | 超出后 |
|---|---|---|
| 同一邮箱登录失败 | 15 分钟内 5 次 | 该邮箱 15 分钟内登录一律 429（即使密码正确），防止针对单个账号的暴力破解 |
| 同一 IP 登录失败 | 15 分钟内 20 次 | 该 IP 429，防止撞库 |
| 同一 IP 注册 | 1 小时内 10 次 | 429，防止批量注册 |

登录成功会清零该邮箱的失败计数。

## 6. 前端

- 路由：`/login`、`/register` 公开；其余页面需要登录，未登录时跳转到 `/login?next=原地址`，登录后跳回；
- 登录状态来自 `GET /api/auth/me`（TanStack Query 缓存）；登录、注册、退出后刷新该缓存；
- API 客户端对所有修改请求自动带上 `X-BookKeepX-Client` 头。
