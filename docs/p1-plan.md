# P1 MVP 实施计划

- 起点：`v0.0.1`（P0 设计与探针完成）
- 终点：`v0.1.0`（MVP 可用：注册登录、手动记账、账单导入、分类规则、统计、Docker 部署）
- 依据：[架构设计](./architecture.md)、[ADR-0001~0005](./adr)、[路线图](./roadmap.md)

## 1. 做法

- **纵向切片**：每一步都同时包含 服务端接口 + 前端页面 + 测试，做完即可在界面上使用，而不是先做完全部后端再做前端。
  （路线图原先把"前端各页面"单列为一步，这里调整为分散到每个功能步骤中。）
- 每一步一个分支，完成后请负责人确认再合并到 `main`。
- 探针代码（`probes/`）不直接搬进生产：按正式规范重写，探针的测试用例与夹具作为正式测试的起点。
- 每一步的完成标准：
  1. 正向 + 反向 + 边界测试齐全，并做"故意改坏"验证；
  2. `pnpm check`（格式 + 代码检查）、`pnpm typecheck`、`pnpm test` 全部通过，CI 通过；
  3. 中文注释覆盖导出的函数、类型和复杂分支；
  4. 相关文档同步更新。

## 2. 步骤

| # | 分支 | 内容 | 完成标准（除通用标准外） |
|---|---|---|---|
| P1-0 | `chore/p1-skeleton` | 正式单仓骨架：`packages/core`、`packages/contracts`、`apps/server`、`apps/web`；Biome、TypeScript、Vitest；开发用 Docker Compose（PostgreSQL）；GitHub Actions CI；健康检查接口 + 前端首页 | 一条命令起开发环境；前端页面能显示服务端健康状态；CI 绿，且故意引入格式 / 类型 / 测试错误时 CI 会红 |
| P1-1 | `feat/core-money` | 金额模块：元 ↔ 分、格式化 | 覆盖探针中发现的全部金额写法 |
| P1-2 | `feat/server-db` | 全部数据表 schema + 迁移；预置分类种子；仓储层按用户隔离 | 迁移可重复执行；隔离有反向测试 |
| P1-3 | `feat/auth` | 注册 / 登录 / 登出 / 会话；限流；CSRF；登录页、注册页 | 密码错误、会话过期、越权访问均有反向测试 |
| P1-4 | `feat/categories-accounts` | 分类树（预置 + 自定义、隐藏）、资金账户；管理页面 | |
| P1-5 | `feat/transactions` | 手动记账：增删改查、筛选、软删除；记账页、流水列表 | |
| P1-6 | `feat/import` | 导入管线：通用引擎 + 内置模板迁入 core；上传 → 识别 → 解析 → 自校验 → 退款关联 → 去重 → 自动分类 → 预览 → 提交 / 整批撤销；导入页 | 真实样本全链路；自校验不过时拒绝导入 |
| P1-7 | `feat/import-custom-template` | 识别失败时的列映射向导，保存为用户模板 | 用户模板能被后续识别自动选中 |

| P1-9 | `feat/stats` | 月度汇总、分类占比、趋势；统计页（ECharts 按需引入，统计页单独拆包） | 口径与 P0-2 探针一致 |
| P1-10 | `feat/pwa` | PWA 清单、图标、移动端适配 | |
| P1-11 | `chore/deploy` | 生产 Docker 镜像（多阶段构建）、部署文档、备份说明 | 在干净环境按文档一次部署成功 |
| P1-12 | `test/e2e` | Playwright 端到端：注册 → 记一笔 → 导入 → 看统计 | |
